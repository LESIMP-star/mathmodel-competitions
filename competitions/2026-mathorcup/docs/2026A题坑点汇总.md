# 2026 MathorCup（妈妈杯）A题 坑点汇总（实测核验版）

> 以下所有数字均已用 Python 直接读取附件逐一验证（2026-10-24），与题目文字口径冲突处一律以实测为准。
> 标注 ✅ = 原坑点经实测证实；⚠️ = 原表述与实测不符，已修正；🆕 = 实测新发现的坑。

## 一、基础数据附件致命大坑（第一张图）

1. ✅ **3.xlsx**：不是标签文件，是空白评分卡。实测含 **13 个 sheet（beer_1~beer_12 + summary）**，评分公式 **1260 个**（原说 54 个），缓存值全部为 0；summary 的 12 行也全为 0。⚠️ 注意：**Sheet2 空表在 8.xlsx 里，不在 3.xlsx**。3.xlsx 只提供 0–6 评分卡的结构（Aroma/Flavour 双栏、各维度描述语），**不提供任何真值**。
2. ✅ **4.csv**：存储的是**中心化/标准化分数，不是原始 0–6 分**（值域实测 -2.15 ~ 6.17）；它和 3.xlsx summary 的列顺序在后 19 列**错位 18 对**（body/co2/aftertaste/alcohol 区 与 acidity/sweetness/dms 区整体互换），直接按位置拼接必错。
   - 🆕 **最关键：0–6 原始分不可精确反解**。对 4.csv 做平移搜索和逐列仿射搜索（mu×sd 网格），最优残差仍有 0.11–0.15，落不到整数格点。Q1 只能做**近似等级映射**（如分位数切分 / Q-Q 映射），并在论文中明确说明这一局限——不能写"反标准化后取整"这种评审一复现就穿帮的话。
3. ✅ **1.csv**：浓度是 **log10 变换后的值，负值不是异常值**。实测连** pH（10^0.614=4.11）、ethanol（10^0.804=6.37 %vol）、color（10^1.33=21.4 EBC）、bitterness（10^1.145=14.0 IBU）、CO2（10^0.30=2.0 PSI）** 这五个"号称保留原始量纲"的列**也全是 log10**——PDF 说它们保留原始量纲是错的。
   - 🆕 **6807 个格子的值精确等于 -1.817819（=10^-1.8178≈0.0152），是检测下限 LOD 填充值**，不是真实浓度，须与真值区分处理。
   - 🆕 **9 列存在真 NA**：X2.3.butanedione(diacetyl)、X3.methylbutanal、ethyl.isobutyrate、methylpyrazine、furfural、amyl.acetate、phenylacetaldehyde、ethyl.nicotinate、aroma_hops_sum。NA 插补与 LOD 截断是两种不同的处理叙事，不能混为一谈。
4. ⚠️ **7.csv**：250×189（**186 个感官列** + 3 个 meta 列）。**3 个整列全 NA 的空列：palate_acetaldehyde、palate_acetate、palate_dentist**（750 个 NA 全部在这 3 列），Q1 建模前必须删除。标签集与 4.csv 是两套体系：同概念列相关性弱（如 4.csv A_malt_all ~ 7.csv aroma_malt 仅 r=0.45），**不能混用**。

## 二、文本口径矛盾坑（第二张图）

1. ✅ 样本数量矛盾：正文写一共 226 种啤酒，**实测全附件都是 250 行/250 个 beer**；PDF 写相关性用 Pearson、数据说明 txt 写 Spearman，**实测 2.csv 与 1.csv 的 Spearman 完全一致**（抽样三组 0.1861/0.5761/-0.0070 分毫不差，Pearson 不符）→ 论文按 **Spearman** 口径做。
2. ✅ 量纲陷阱：175 列存在 log10 变换（min<0）；pH、color 等被压缩，**且比题目字面说的更严重——五个理化列全在对数域**。
3. ⚠️ 评分映射坑：Q1 要求输出 0–6 离散等级，但 4.csv 的中心化分数**不可精确反解**，只能近似映射（分位数切分等），必须写明局限。
4. 🆕 **6.csv 实测是 44×50**（题目写 46×50 是错的）：44 化合物 × 50 感官属性的 Spearman 交叉相关矩阵（已用 ethyl_acetate~A_malt_all=0.2561 精确复核）。5.csv 实测 51×51 = 4.csv 50 列的 Spearman（0.6079 精确复核）。

## 三、Q2 风味归因的误导 AI 坑（最容易丢分）

1. ✅ 附件 8 已经直接给出 GBM、MDI、SHAP 的排序结果，**不能直接拿这个排序作为 Q2 的 Top-3 结论**。
   - 🆕 实操细节：GBM SHAP 表为 500×236，**必须剔除 base_prediction 干扰列**（其 mean|SHAP| 最大、纯干扰）；data 列区分 SHAP / concentration 两块。直接用均值排名会踩坑。
2. ✅ 硬性要求：必须额外增加 bootstrap 重采样入选频率检验、跨模型方法间 Jaccard 稳定性检验，还要结合啤酒化学机理、文献做风味基团的合理性论证。
3. ✅ 禁止直接跑通模型就上交结果，只输出排序会判定为 AI 套壳。

## 四、Q3 风格生成：小样本反 AI 约束坑

1. ✅ 250 样本属于小样本条件（22 个风格，最小类仅 3 个样本），生成谱必须落在阈值可行域内。
2. ✅ 必须约束缺陷物：DMS、双乙酰 Diacetyl、4VG 这类不良风味物质，生成时不能恶化超标。
   - ⚠️ 阈值口径：8.xlsx Sensory thresholds 表 261 行中**仅 43 行有阈值数值**。实测：DMS=17.25 µg/L（中位 19.0）、Diacetyl=0.299（中位 0.09）、4VG=0.206（中位 0.20），**但 t2n（trans-2-nonenal）在表里没有阈值数值**——必须引文献补阈值，不能假装表里有。
3. ✅ 酯类、萜类、硫化物等风味基团，不能单纯靠模型生成，需要对照阈值表、文献做人工化学合理性论证。

## 五、统一硬性反 AI 评审要求（整道题都要遵守）

1. ✅ 结论必须可复现，不能只给跑出来的模型结果。
2. ✅ 稳定性、不确定性分析，必须做真实的重采样（bootstrap）计算。
3. ✅ 化学合理性必须人工论证；题目里多处口径矛盾，一切以实测数据为准，不能照搬题目文字描述。

## 🆕 六、实测新发现的坑（原汇总未覆盖）

1. **8.xlsx 的 "Calibrated chemical dataset"（250×73）是 1.csv 的"解密对照表"**：批量验证 70 个共同列中 **35 列 = 10^(1.csv 值)**、**33 列 = 1.csv 原值**。Q1 预处理可直接用它做 log10 还原与校验，比"自行判断变换底数"稳得多。
2. 8.xlsx "Sensory names" 表（101 行）给出全部感官属性的 R_name ↔ 论文名 ↔ 分类（Trained panel 50 / Ratebeer 51；Yeast 24 / Hops 20 / Malt 20 / Others 23 / Wild flora 4）映射——**5.csv/6.csv/7.csv/4.csv 之间的列名对齐全靠它**，不要手写映射。
3. Beer Prices 表：Price 缺 164/250（基本不可用），ABV 完整——Q3 若用价格/ABV 做辅助约束，只能用 ABV。
4. tasting_category_fine（7.csv/1.csv）与 tasting_category（Beer Prices）是大小写不同的同一套 22 类标签（Blond 31 / Tripel 28 / … / faro 3），注意统一前做字符串归一化。

## 一句话总结踩链

> 数据预处理错一步（对数还原、LOD/NA 分离、列对齐）→ Q1 全错且不可复现；Q2 只抄 SHAP 排序、不加稳定性检验直接丢大分（记得先剔 base_prediction）；Q3 生成不约束不良物质、不做化学校验直接被判 AI 生成（t2n 阈值表里没有，要引文献）。
