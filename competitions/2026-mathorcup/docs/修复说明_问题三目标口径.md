# 问题三修复说明：目标函数与约束的权重口径不一致

修复日期：2026-10-30
影响范围：问题三全部结果（Pareto 前沿、表 12、表 15、灵敏度、9.2 节、结论、摘要）

---

## 一、问题是什么

`q3.py` 里同一条"干预代价" $f_3$ 有**四处定义**，其中三处带 $w_j$ 归一化、一处没带：

| 位置 | 代码 | 是否带 $w_j$ |
|---|---|---|
| $\varepsilon_3$ 约束 | `add(r, i_dp + j, lam * wj[j])` | 带 |
| `metrics_of`（报告用） | `f3 = lam * sum(wj * abs(dx))` | 带 |
| `_obj_vec`（重解用） | `lam * wj` | 带 |
| **默认目标向量 `c`** | `c[i_dp] = lam` | **不带** |

后果是**求解器优化的目标函数不是论文报告的那个 $f_3$**。实测差值：

```
e_f3（约束里的 f3）= 10.2245
f3  （报告出来的 f3）= 7.4510
```

也就是说约束允许的改动量被 $w_j$ 加权（按各列可行域宽度归一），但目标函数里按"原始幅度"计价。$w_j = 1/(ub_j - lb_j)$，而决策列里既有宽 87.5 的线性浓度列、也有宽约 6.9 的 $\log_{10}$ 列，两者原始幅度差一个量级——**不加权等于让目标函数偏爱改动线性浓度列**，因为它看起来"便宜"。

## 二、怎么发现的

不是外部报告指出的，是核查 `论文第二轮_问题诊断报告.md` 第 35 条时顺带发现的：检查 `metrics_of` 的 $f_3$ 定义与 `solve_milp` 的目标向量 `c` 是否同口径，发现差一个 `wj`。

判据：求解后应有 `e_f3 - f3 >= 0`（约束 $f_3 \le \varepsilon_3$ 恒成立）。修复前出现负值，即报告指标违反了求解时的约束——**这是自相矛盾的硬证据**，不是主观判断。

## 三、改了哪三处

文件：`code/q3.py`

### 1. 默认目标向量（第 410–411 行）

```python
# 修复前
c[i_dp:i_dp + n] = lam
c[i_dn:i_dn + n] = lam

# 修复后
c[i_dp:i_dp + n] = lam * wj
c[i_dn:i_dn + n] = lam * wj
```

### 2. 增广项（第 562–563 行）

剔除弱 Pareto 点用的 $c_{\text{aug}}$，其中 $\lambda$ 项同步乘 $w_j$：

```python
c_aug[ix['dp']:ix['dp'] + n] += EPS_AUG * 0.1 / n3s * lam * arr['wj']
c_aug[ix['dn']:ix['dn'] + n] += EPS_AUG * 0.1 / n3s * lam * arr['wj']
```

### 3. 注释（`build_arrays` 返回值处）

把 `wj=wj` 的说明改为"$\varepsilon_3$ 约束、默认目标 $c$、`metrics_of` 三处共用"，防以后再有人只改一处。

## 四、顺带修的第二个缺陷

文件：`code/robustness_q3.py` 第 65 行

主脚本 `q3.py` 在拟合 PLS 代理前把训练集裁到了 MILP 可行域 `[p1, p99]`（因为 `X2.methyltetrahydrofuran.3.one` 的 std 是 795、max 12596，不裁会让线性浓度列独占协方差，成分数塌缩到 2、CV $R^2$ 转负）。但 `robustness_q3.py` 是独立脚本，**漏了这一步**。

后果：灵敏度分析用的代理和主结果用的不是同一个。不裁时基准 $f_1 = 11.0431$，裁后 $f_1 = 20.2063$。若不修，表 15 的基准值和表 12 的 P1 对不上——读者一眼能看出矛盾。

修法是在 `q3.fit_pls_surrogate` 之前补一行 `Xv = np.clip(Xv, lb, ub)`，与 `q3.py` 第 695 行一致。
