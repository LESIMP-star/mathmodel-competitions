## 1. OAV 拿对数值直接相除 —— 误报

**报告主张**：部分浓度以 $\log_{10}$ 保存，直接相除会得到错误 OAV。

**代码事实**（`q2.py:277`）：

```python
conc = 10 ** v if f in LOG10_COLS else v
oav = conc / thr[f]
```

先判断该列是否属于对数域，是则 `10**v` 还原成线性浓度，再除阈值。**没有直接拿对数值相除**。

**但报告间接指出了一个真问题**：论文 7.3 节写"30 个阈值在 $\log_{10}$ 域、13 个在线性域"。查附件 8 的 `Sensory thresholds` sheet：43 个有数值的阈值**全部是线性浓度**（mg/L 或 $\mu$g/L），不存在"在 $\log_{10}$ 域的阈值"。分域的应该是**浓度列**，不是阈值。

已改为：231 个浓度列中 182 列在对数域、49 列在线性域；43 个阈值全部为线性浓度，比较前先把浓度还原到线性域。

## 2. 整组置换 vs 逐列置换 —— 真问题（最严重）

**报告主张**：正文称按化学族整组置换，代码每次只置换一列。

**代码事实**（`q2.py:209-211`）：

```python
for j in range(p):
    Xp = X.copy()
    Xp[:, j] = Xp[rng.permutation(n_ev), j]     # 只打乱第 j 列
```

确为逐列置换。

**更严重的是**：原文还写"族内按 $\pi_g$ 比例分解出单列 $\pi_j$"。这在数学上做不到——整组置换只产出 7 个族级数值（7 个化学族的 $\pi_g$），要落到 212 个香气化合物各自的排名，必须人为摊派比例，而**摊派方式本身决定排名**。不是实现问题，是方法宣称超出了方法能力。

**处理**：保留逐列置换（它才是真正被执行的、且能给出单化合物排名的方法），把正文改成"逐列置换重要性 + 入选频率"，并写明代价：同族化合物互相顶替会低估单个化合物的重要性（Strobl 等 2008），故用 200 次重采样的入选频率 $\pi_j$ 做稳健化。数值全部不变。

## 3. q=0.05 算出 0.50007 —— 数字误报，但"控制 FDR 0.05"无依据

**报告主张**：按 $q=0.05$、$p=350$ 代入 $\min(0.95, \max(0.5, (1+q/p)/2))$ 得 0.50007，与正文 0.5022 不符。

**代码事实**：`Q_TARGET = 1.0`，$p = 231$，$(1+1/231)/2 = 0.50216$ → 与正文 0.5022 完全吻合。报告用错了 $q$ 和 $p$。

**但"严格控制 FDR ≤ 0.05"的说法确实无依据**。这个阈值来自 Meinshausen & Bühlmann (2010) 的稳定性选择准入界：

$$E[V] \le \frac{q_{\text{sel}}^2}{(2\pi_{\text{thr}}-1)\,p}$$

其中 $q_{\text{sel}}$ 是**基础选择程序每次选出的变量数**（本题 `TOP_MEASURE = 10`），不是错误发现预算。

- 代码用 $q_{\text{sel}} = 1$ → 0.5022，只是一个**操作性阈值**（"每次只选 1 个变量时的准入线"）
- 按原义 $q_{\text{sel}} = 10$ 代入 → **0.7165**，本文未采用

另外，论文写的"500 行置换零分布""350 个检验""控制 FDR 0.05"三样在代码里都不存在。

**处理**：正文保留 0.5022（数值对），删掉 FDR 控制表述，改称"稳定性准入阈值"，并在 `fdr_threshold` 的 docstring 里写清 $q_{\text{sel}}$ 的真实含义与 0.7165 这个备选值。

## 4. 内层预处理在外层训练集估参 —— 真问题，已修

**报告主张**：`nested_cv_one` 在内层切分前用整个外层训练集算中位数和标准差。

**代码事实**（`q1.py:237-246`，修复前）：先在整个外层训练集上算 `med`/`sd`，再 `kf_in.split(A)` 切内层。内层验证折的信息确实参与了预处理参数估计。

**影响边界要说清**：这只影响**内层模型选型**（超参数/模型族的挑选可能偏差），**不影响外层测试集**（外层测试集始终未参与任何估参）。所以不能说"性能虚高"，只能说"选型不够严格"。

**顺带发现的第三处不一致**：`q1.py:239` 用 `np.nanstd(np.nan_to_num(Xtr_raw, nan=0.0))` 算标准差，把缺失当真值 0，而填补用的是中位数——同一份数据用两套口径。

**处理**：新增 `_fit_prep`，把中位数填补 + 标准化移入**内层训练折内**逐折估计，同时修 `sd` 的缺失处理。全量重跑 393.5 s：

| $R^2$ 均值 | 0.2219 | 0.2223 |
| $R^2>0.3$ 维数 | 13 | 14 |
| 区间宽度中位 | 0.1968 | 0.1936 |

## 5. 4VG 的 −2.0132 不是 0.206 mg/L 的对数 —— 真问题（措辞）

**报告主张**：$\log_{10}(0.206) \approx -0.686$，与约束用的 −2.0132 不等。

**代码事实**（`q3_full.log:16`）：

```python
cap = min(log10(theta), x0)
```

- DMS：$\min(1.2368,\ 1.5873) = 1.2368$ —— **阈值**决定
- 4VG：$\min(-0.6854,\ -2.0132) = -2.0132$ —— **"不恶化"约束**决定（基线本身已低于阈值）

所以 −2.0132 是基线值，不是阈值的对数换算。数值对，解释错。

**处理**：正文改为"取 $\min(\log_{10}\theta,\ x_0)$，4VG 处取更严格的基线上限 −2.0132，该值不是阈值的对数换算"。

## 6. 两段式公式与文字不一致 —— 误报

**报告主张**：正文的"出现概率—出现后强度"叙述与加权混合公式不一致。

**代码事实**（`q1.py:187`）：

```python
out = (1.0 - pi) * y_floor + pi * mu
```

与论文式 (5) $\hat y = (1-\hat\pi)\bar y^{\text{floor}} + \hat\pi\hat\mu$ 逐项对应，无偏差。

**但术语确实该改**：附件 4 的标签按品评员做过 z-score（文献原话 "scaled by standard deviation and mean-centered per taster"），负值表示"低于该品评员的平均"，**不是"没有尝到"**。所以 $1-\hat\pi$ 不能叫"未出现的概率"。

**处理**：全文"未感知"改为"左尾"（$y \le y_s^{\min} + 0.15$），$1-\hat\pi$ 解释为"落在左尾窗的概率"。
