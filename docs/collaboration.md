# 协作规范

## 一、分支

| 分支 | 用途 |
|---|---|
| `main` | 稳定分支，随时可编译、数字可核对 |
| `feat/<名字>-<内容>` | 新功能，如 `feat/wujiawen-q3-milp` |
| `fix/<名字>-<内容>` | 修 bug，如 `fix/lisi-q1-overflow` |

不直接往 `main` push。做完提 PR，至少一人 review 后合并。

## 二、提交信息

一行说清做了什么，必要时第二行写为什么。

```
q2: 分组置换改用化学族为单位，修正逐列打乱低估的问题
paper: 6.3 节补超参表，正文压到 30 页
fix: 修正 Q3 网格数 280 与 300 的表述矛盾
```

## 三、结果文件契约

论文正文里的每个数字都必须能溯源。约定：

- 每个结果文件由某个脚本生成，生成关系写在 `results/README.md`
- 论文写作时引用结果文件，不手抄数字
- 结果变了就重跑脚本、重编译论文，不手动改正文数字

反例（会导致对不上账）：脚本改了但论文没重编；两个脚本写同一个结果文件；手动改 CSV。

## 四、图表

- 绘图脚本统一放在 `code/figures.py`，每个图一个函数
- 图内不写死数据，一律从 `results/` 读
- 图注写结论，不写"图 X 展示了……"
- 同一节的图不超过两张

## 五、论文

- 正文页数按赛事规定控制，附录不计
- 摘要四段：总述 → 问题一 → 问题二 → 问题三，每段按"难点 → 方法 → 结果"
- 正文不出现全角括号做补充说明，改用逗号分句
- 编译前删掉全部生成物，`xelatex` 跑两遍

## 六、不许做的事

- 往仓库塞赛题原始数据（几百 MB，且属于赛事方）
- 提交 `.env`、token、license 文件
- 直接改 `main` 的历史
- 提交超过 20MB 的单个文件（用网盘，仓库只放脚本和结果）
